# Root cause analysis: what 23.13.0 changes and why

| Reported or requested | What was found in 23.12.0 | Cause | Change in 23.13.0 |
|---|---|---|---|
| Scripts are generated and run with Chromium although Edge is preferred (AI-Driven, Discovery, Hybrid) | On an office PC with only Edge, script generation and Discovery failed or used the wrong browser. | Many callers passed the literal `"chromium"` as their default, which overrode Preferences; a browser that was not installed was an error with no fallback. | `browser.preferred()` treats `"chromium"` as "the default browser" and follows Preferences; `launch()` falls back (Preferences, Edge, Chrome) only for a browser that is not installed, and logs the switch. The exported pytest scripts and the framework template use the same rule. |
| Male voice chosen, female voice answers (offline) | The reply came in Microsoft Zira (female). | When the Windows voice could not be used, the browser fallback spoke with the first voice of its own list. | The fallback picks a voice of the chosen gender (male by default); Arabic replies use an installed Arabic voice of the same gender. |
| Arabic and UAE Arabic commands | Arabic speech was pushed to English words, and Arabic text was not understood. | The recognizer was given an English vocabulary hint and the English language; the command parser is English. | Recognition runs in "auto" (English and Arabic) without the English hint for Arabic; the command is translated to English by the local AI (a word list when the model is offline), runs, and the reply is translated back. |
| Defect Review: "Assign to" from TFS | A free-text field on some defect types only. | No API for the project's people; the draft had no assignee column. | `team_members()` + WIQL assignees, `GET /api/defects/assignees`, migration 22 (`assigned_to`), `System.AssignedTo` on publish, the dropdown on every draft. |
| Guided Browser layout | Version history above the script, a short Python area, no tabs. | Layout of 23.6. | Tabs as in AI-Driven, full-width 720 px Python area, version history last. |
| API Testing: Open did nothing visible | The results card was drawn below the fold. | The click updated a card the person could not see. | The card is drawn, scrolled into view and the row is marked. |
| API Testing: TLS FAIL on an offline PC although Edge opens the API | `CERTIFICATE_VERIFY_FAILED` against an intranet API. | Only the `certifi` public bundle was trusted; the company CA is in the Windows store. | The SSL context loads the system store (Windows ROOT/CA), certifi and the application's CA file. Verification stays on. |
| HTTPS with a name instead of IP / PC name | Only `http://<ip>:8765`. | Not supported. | Local CA and server certificate made on the PC (standard library), a second uvicorn server on the HTTPS port, the Host check accepts the configured name, `ENABLE_HTTPS.cmd` / `TRUST_SKYGUARD_QA.cmd` for trust, hosts and firewall. |
| AI Agent: after choosing *lifecycle* the other dropdowns disappear | The Knowledge tab showed "could not be loaded" and lost its controls. | The API's `Kind` list did not include `lifecycle`, so the request was refused (422) and the tab replaced its content with the error card. | `lifecycle` accepted; a filter that fails is reset when the tab is retried. |
| AI Agent asks for an account on a public website (Emirates) | "I need an account" although the person taught that none is needed. | Every application was assumed to need a sign-in. | A *public* flag per application ("no account and no need of account" in chat, or the checkbox); the waiting request continues without an account. |
| AI Agent: dynamic URLs | Moving from `www.` to `fly4.` or a new session path was treated as leaving the application. | Origins were compared exactly. | `same_site()` accepts other host names of the same registrable domain and scheme; runner `goto` / `expect_url` match changing IDs and tokens. |
| AI Agent: a new browser for each command | Each command opened a new window and lost the sign-in. | The chat did not keep its browser. | One chat browser per session, signed in once; a new window only when asked. |
| Healing is not kept | The same locator healed on every run. | Healed locators were only proposed; `auto_apply_healing` was off and nothing wrote them back. | A healed locator whose step passed is written into the script (old one kept as an alternate, new version); a person's click while paused becomes the locator; on by default. |
| Users: personal PAT, project, email, welcome email | One shared TFS connection for everyone; no email. | Not supported. | Required fields, PAT checked and stored per person, TFS data and caches per person and project, welcome email with the manual. |
| Report buttons on every testing page | Only the dashboard had an AI report. | — | One bar (Generate AI result, Create TFS defect, Send email PDF) on 15 pages; report kind `module`. |
| Analytics AI and PDF | None. | — | AI analysis card on Analytics. |

# Root cause analysis: what 23.12.0 changes and why

| Reported or requested | What was found in 23.11.2 | Cause | Change in 23.12.0 |
|---|---|---|---|
| Remove "offline, no administrator rights" from the Setup window (screenshot) | The footer of every wizard page read "SkyGuard QA 23.11.2  offline, no administrator rights". | `BrandingText` in `packaging/setup/SkyGuardSetup.nsi` carried the phrase. | `BrandingText "SkyGuard QA ${VERSION}"`. The version label is kept; the Welcome text still explains the upgrade. |
| Agent Workflow cards said READY although the engine could not work | A card was READY whenever no run was active, even with the local AI offline or Playwright missing. | `/api/agents` returned only the event state; nothing checked the agent's dependencies. | `api/core.py` `_availability` adds `available` and `unavailable_reason`; the card shows UNAVAILABLE with the reason. The page layout is unchanged. |
| Missing agents on Agent Workflow | The AI Agent (operations), Integration Comparison and scheduling did their work without a card; API Testing did not exist. | Those services never emitted agent lifecycle events and were not in `agents/registry.py`. | Six agents registered once each, and each service emits started / progress / completed / failed / paused through `BaseAgent.activity` (the operations engine through `_CardReporter`). |
| Integration Comparison in Scheduled Runs, and drafts for differences | A saved comparison could only be run by pressing RUN COMPARISON; a mismatch became a defect only when a person pressed Create defect. | The scheduler only knew AI-driven, Guided and Hybrid scripts. | A provider interface on the scheduler (`providers`), `ComparisonScheduleProvider` (`CMP:<id>`), and `comparison/schedule.py` turns every confirmed mismatch into a review draft (at most 25 per run). |
| API Testing module | None. | New. | `qa_platform/apitesting/*`, `api/apitesting.py`, `web/js/pages/api-testing.js`, migration 21, `ApiScheduleProvider`. |
| Execution mode shown with its reason | Scheduled Runs offered "Visible / Hidden" only; results did not say how they ran. | — | Visible / Headless / Smart Auto; each result keeps `mode` and `mode_reason`. API items always run as Authorized API/HTTP and say so; a browser test is never replaced by API calls. |
| Larger Python editor | Fixed maximum height of 620 px, no full screen, errors only listed above the code. | CSS `max-height` and no resize. | Resizable height (remembered), Taller / Shorter, Full screen, error lines marked in the gutter. |
| A per-test timeout in API runs (found while testing) | A test's own timeout was ignored, and the next tests of the run kept the changed configuration. | The client was created once per run with the application timeout. | The timeout is passed per request. |
| `{{column}}` in an assertion (found while testing) | Data-row values were filled into the request but not into the expected values. | Assertions were evaluated as written. | Expected values are filled from the row and extracted variables before they are checked. |
| HTTPS test CA rejected (found while testing) | "CA cert does not include key usage extension". | Python 3.13 verifies certificates strictly; the test CA lacked key usage. | The test CA now has the extensions a real CA has. The product behaviour (refuse) is kept and documented. |
| Upgrade refused at Verify by the 23.11.0 check (found in the first Setup run under Wine) | "Python editor, Smart Wait, Defect Review (23.11.0) FAIL"; Setup rolled back to 23.11.2 and nothing was lost. | The 23.11.0 check counted exactly 6 failure classes; 23.12.0 adds 3 for API failures. | The check now requires the six 23.11.0 classes to be present. Setup was run again: every check passed. |
| SkyGuard would not start where python-multipart is missing (found by CI on the pull request) | The Linux CI jobs could not start the application: "Form data requires python-multipart". The offline Windows runtime does not have that package either, so the first upgrade package built for this release would have installed but not started. | The certificate upload of API Testing was a multipart form; FastAPI needs python-multipart for that, and it is not a SkyGuard dependency. Setup's *Application loads* check imported the application but not the API modules, which are imported only when the server starts. | The upload sends the file as the raw request body, so no new package is needed. *Application loads* now imports every API module; with the old code it fails with this exact message. The release was rebuilt and Setup run again under Wine with the offline runtime (which has no python-multipart). |
| AI Agent "Finish lab" refused on SauceDemo (reported on the first package) | *not authorized: The signed-in identity has not been verified from the application*, although the sign-in worked; 23.11.2 had fixed this for applications that never show the signed-in user. | While learning, the agent turns the sentence that shows the signed-in user into a rule. SauceDemo's sign-in page lists *Accepted usernames are: standard_user ...*, so a rule was made from that help text. With any rule stored, 23.11.2 no longer accepted "the application accepted this sign-in" as enough, and the rule never matches a signed-in page. The SauceDemo stand-in used for testing did not have that help text, so the tests did not see it. | Help text that lists user names or a password for all users never becomes a rule. A stored rule that finds nothing no longer blocks the run (a different user shown by the application still stops it). The stand-in now has SauceDemo's help text. |
| Integration Comparison *Apply filters*: InvalidSelectorError (reported) | `button[name=/(?i)^(apply\|search\|filter\|go\|show)/i]` refused by the browser. | The Python flag `(?i)` was written inside a JavaScript regular expression, which does not accept it. | The case-insensitive flag is passed the JavaScript way. If there is no Apply button, the table is taken to filter as values are typed, and the log says so. |
| Integration Comparison INCOMPLETE "page 6 repeats an earlier page (Next did not move on)" (reported on tabulizer.com) | Every record was read, but the capture was marked INCOMPLETE. | That table keeps its Next button active on the last page; SkyGuard took "Next did nothing" as a failure. | On a repeated page SkyGuard checks the application's own record count ("Showing 51 to 57 of 57 entries") or its last page number; if they agree with what was read, the capture is complete. |
| Setup shows "Unknown publisher" (reported) | SmartScreen: *Publisher: Unknown publisher*. | Setup.exe had no publisher in its properties and is not code-signed. Windows reads the publisher only from a signature. | Publisher Muhammad Tufail in the properties and on the Welcome page; optional signing in the build when a certificate is given. SmartScreen's text changes only with a signature. |
| API run shown as finished before its failures were classified (found by the Windows CI job) | For a moment a FAILED run had results without a classification or Defect Review draft. | The run's final status was saved before the failure analysis ran. | The final status is saved after the analysis (also if the analysis fails). |
| AI Agent "Finish lab" on Swag Labs FAILED / Uncertain after a complete order (reported) | Every step ran up to "Thank you for your order!"; the run said "no success message or record was found after submitting". | The task was learned as successful because the page moved on after Finish, but only a success *message* was kept for checking later runs. Swag Labs shows none, so nothing could confirm the run. The SauceDemo stand-in had never been used for an AI Agent run. | The result page is learned with the task and checked after the submit (a different page, no error, no sign-in form). Tasks learned before have no result page: a new page that says "Thank you", "successfully", "order complete" and the like confirms them. Tested end to end on the stand-in with the reported answer "bilal; ahmed; 3432". |
| "buy item" not found by its own name (reported) | "I have not learned how to create item"; the self-test showed "1 item not found again". | A task's kind was taken from its last click ("Finish" = complete), not from the name the person gave it ("buy" = create). | The name's verb is accepted as well (never for approve / reject). |
| "Zip/Postal Code must be unique" (reported) | A rule suggested for the recorded task. | Recording suggests "must be unique" for every field whose name ends in "code", "no" or "number". | Postal, country, phone, currency and similar codes are excluded. |

## The AI Agent (part A of the request)

The SauceDemo flows (login, add to cart, checkout; missing information; previews; paused / uncertain runs) were
repaired in 23.11.1 and 23.11.2, which this upgrade contains. 23.12.0 adds the AI Agent's card on Agent Workflow
with the real end state of each run (a run that stops for a decision is shown as PAUSED with the reason). After the first
delivery, one more root cause was found from the report on SauceDemo (the identity row above). saucedemo.com could not be reached from the build machine
(the network refused it, HTTP 403), so the flows were checked on the local SauceDemo stand-in (`tests/site/saucedemo`)
and the stand-in shop (`tests/shop_site.py`); see TEST_REPORT.md.

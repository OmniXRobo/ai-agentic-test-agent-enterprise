# Patch 23.3.30: SkyGuard QA branding, navy voice pages, Agent Workflow scene, report PDFs and acceptance criteria

Cumulative patch for 23.2.2 and 23.3.0 to 23.3.29.

## What is new

**Product name, tagline and logo (Settings > Preferences > Product name and logo)**

* The product is now called **SkyGuard QA**, with the tagline *Every release, cleared for takeoff.* (it was
  "QA Enterprise AI / Automated quality. Defended.").
* Both can be changed under Preferences (name up to 40 characters, tagline up to 80; an empty tagline hides it).
* Logo file path: a PNG, JPG, GIF, WEBP or SVG file on this PC, up to 2 MB (a square image looks best). Quotes
  pasted with the path from Explorer ("Copy as path") are removed. The path is checked when you save; a missing or
  unsupported file is refused with the reason. If the file is removed later, the built-in emblem is shown again and
  Preferences says why. The server serves the file at `/api/branding/logo` (a web page cannot open a local path
  itself; an SVG opened on its own cannot run scripts).
* The name, tagline and logo appear in the header (top left), the browser tab titles, every report (HTML and PDF,
  also the performance run, comparison and consolidated reports) and the PDF page footer, scheduled-run and test
  emails (the sender name, unless one is set under Outlook Email), TFS test run comments, test data written to TFS
  and the schedule messages.
* Kept as they are, on purpose: the install folder, the patch scripts and the Windows sign-in startup file name, so
  later patches and the startup entry keep working. Text the application writes into generated test cases and scripts
  ("Generated by AI Agentic Test Agent Enterprise") also stays, because it is used to recognise them.

**Voice pages in navy and cyan**

* AI Voice Command Center and Voice & Command Agent use the navy and cyan of the other pages instead of the
  night-vision green. The Air Force console stays: radar with its sweep, mic ring, callsign, monospace tactical
  labels, amber channel tags and HUD corner brackets. Red while listening and amber while thinking are kept, so the
  microphone state still shows.

**Agent Workflow: the Air Force scene on top**

* The jets and radar were drawn behind the agent cards and covered by them. A banner at the top of the page now
  shows a formation of fighters crossing the sky, radar rings with a sweep and blips, the title *Air Defense
  Operations · Agent Squadron* and the Airborne / On standby / Down counts. The cards below stay as they were.
  Motion stops when Windows "reduce animations" is on.

**Report PDFs**

* The report page is opened from a file next to the PDF instead of being sent to the browser in one message. A report
  with many evidence screenshots could take longer than the browser's 30-second default, and the PDF was not made;
  the wait is now up to 3 minutes.
* The browsers bundled with the package are used even when the application was not started from its launcher.
* If the included Chromium cannot start (for example blocked by a company policy), Microsoft Edge and then Google
  Chrome print the PDF instead. If none can, the report says what each browser answered.
* Reports list: **Open PDF** (in the browser), **Download PDF**, and **Make PDF** for a report whose PDF is missing; it
  prints the saved report again without collecting anything again.

**Dashboard: Acceptance Criteria count**

* The count read only the Acceptance Criteria field of user stories. Projects that keep criteria as their own work
  items (an "Acceptance Criteria" type linked under the story) showed nothing. The dashboard now counts both: the
  criteria written in the field and the criteria work items, and "on N of M user stories" counts a story that has
  either. The work item types are the ones the TFS hierarchy uses (Settings > TFS hierarchy override, otherwise every
  type whose name contains "Acceptance"). When the count cannot be read, the card shows the reason.

## API

* `GET /api/branding` {name, tagline, logo, logo_url, logo_problem}; `GET /api/branding/logo`
* `PATCH /api/settings` `ui.brand_name`, `ui.brand_tagline`, `ui.logo_path` (checked)
* `POST /api/reports/{id}/pdf`: print the PDF again from the saved report
* `GET /api/analytics/summary` `acceptance_criteria` adds `in_field` and `work_items`
